## 2. 致命问题（5 条，全部实测复现）

### E1 每次读档都重新发放新手武器 → 无限锻造尘
- **代码**：`migrate()`（game-data.js 约 L456）`if(!Object.keys(s.inventory.equipment).length){s.inventory.equipment.eq001=1;…}` —— **没有一次性标记**（对比同文件 L434 的 `rewardBackfills.v215` 是有标记的），而 L418 又会删掉数量为 0 的背包键
- **实测**：`分解 eq001 → 重新 migrate → eq001 回来了（还自动装回 h004）→ 再分解`，200 轮循环锻造尘 **0 → 5025**（每轮稳定 +25）
- **后果**：锻造尘是 SSR 套装装备的唯一来源 → 无限套装。云模式下每次云请求都跑一次 migrate，循环更密

### E2 每日/每周重置全部取自本地日期，且可回溯
- **代码**：`gameDay(date=new Date())`、`gameWeek(date=new Date())` 及所有调用方都接受日期参数，且判断用 `!==`（无单调保护）
- **实测**：同一天内 `claimLoginReward(D(0))→第1天`、`D(1)→第2天`、`D(-1)→第3天`，`daily.day` 甚至倒退到 `2026-09-09`；连续传 D(0)…D(7) → **8 次签到全成功**（7 券 + 460 星髓 + 2000 烬币 + 100 星铁 + 2 星语花 + 1 觉醒核），商店每日限购也一起重置
- **后果**：本地模式是默认模式且完全客户端权威 → 改一次时间就能反复刷签到/日常/10 次扫荡/3 个资源裂境/商店/8+6+3 次活动次数

### E3 同一关可以拿两次奖励
- **代码**：`finalizeBattleSession` 先发奖再判断关卡；`startBattleSession` 有 `ACTIVE_BATTLE_SESSION` 互斥但 `battle()` **没有**
- **实测**：留一个手动会话在 `waiting` → 打自动战斗（+470 烬币 +1 券，关卡 3→4）→ 把残留会话打完 → 又是 `win:true, rewards:{coin:470,tickets:1}, drops:1` → **合计正好 2 倍**
- **附带**：UI 表现是"手动模式失效"，刷新页面会静默丢弃那场手动战斗

### B1 云存档不可用 ①：SDK 地址 404
- `cloud-config.js` 里 `sdkUrl: .../cloudbase-js-sdk/**3.0.1**/cloudbase.full.js` → **404 NoSuchKey**；同域 `latest/` 是 200（862KB）
- **现象**：点「连接」立刻 toast「云端组件加载失败」，`StarEmberCloud.connected()` 永远 false

### B2 云存档不可用 ②：后端 403
- 手动注入可用 SDK 后，`bootstrapPlayer` 返回 **403 EXCEED_AUTHORITY**（`Request exceeds granted authority`）
- **附带**：`cloud-bridge.js` 把所有云错误（含 403）统一包装成 `NETWORK_UNSTABLE`「网络连接不稳定，请稍后重试」，误导玩家也误导排障 → 建议按 HTTP 状态/错误码分类

## 6. 玩家视角的问题（来自实际试玩）

> 这轮的结论是我以**全新玩家身份**从零玩到第 9 关、抽 3 次十连后得出的，与技术根因一一对应。

### 😖 最难受的三件事
1. **打完一场战斗，游戏什么也不告诉我** —— 第 1 关打完，屏幕上唯一的变化是顶栏烬币 5000→5390、关卡名变化。打 Boss 赢了也没有任何反馈。**实测 14 次连续采样，胜利画面出现 0 次**。

2. **没有敌人、没有战斗画面** —— 推了 9 关没见过一个敌人的样子；`assets/bosses/stage-5.jpg` 本身就是"橙色圆环 + 星星徽记 + 汉字占位方框"，整包 39 张图除 6 张 Boss 占位图外**全是角色立绘**，没有任何敌人素材。
   → 对应设计图缺口（战斗场景）。
3. **第 16 次升级按钮变灰，游戏不告诉我为什么** —— 没有"烬币不足"、没有"去哪赚"。而答案很明确（资源裂境一次 3300、扫荡一次 100~500、日常一天 2900+）。
   → 对应 **任务 D**。

### 让我困惑的地方

### 做得好的地方（建议保留/放大）
1. **开局很顺**：9.7 秒进游戏，教程 5 步 30 秒走完，立刻拿到操作权
2. **新手十连的爽感到位**：弹窗明写"必得 1 名 SSR"，翻牌有稀有度边框与 NEW/重复标签，结果页有 `SSR 1 / SR 2 / NEW 7 / 碎片 +30`
3. **保底"看得见"且准确**：抽完 10 次从 1/50 变 9/50，界面与存档完全一致
4. **升级反馈很爽**：`✦ RESONANCE UP 绯歌 · Lv.1 → Lv.2 · 战力 +75` + toast —— 说明这套反馈框架是有的，**只是战斗没用上**
5. **日常/资源裂境给得大方**：日常 6 个「领取」一次 +2900 烬币 +3 券；资源裂境一次 +3300 烬币 → 新玩家 10 分钟能攒够两次十连
6. **日常任务会告诉我"去哪做"**：未完成时按钮写「前往战斗」「前往契约」「提升 青禾」
7. **剧情文案超出预期**：9 段对话（「砂海里的信号」「沉港灯火」）有杂志感、有悬念
8. **角色立绘有质量**：这是让我愿意继续抽的原因
9. **数值健康**（实测）：抽卡 3000+2000 次单抽，SSR 3.83%/3.55%，保底上限正好 50/60；职业克制**真实生效**（±18%/-12%，我一开始误判为失效，用正确职业 ID 复测后推翻）；锻造→分解净亏无套利；离线可玩；无内存泄漏与长任务

## 8. 给 AI 改代码时的工程约束（建议一并下发）

1. 纯静态 HTML/CSS/JS，**无框架、无构建、无 npm 依赖**；新增样式追加到 `styles.css`，沿用 `v216-/v218-/m2xx-` 前缀与现有 CSS 变量
2. **不动游戏数值与规则**（概率、消耗、掉落、上限），不改变存档字段语义
3. 所有可点元素必须沿用 `data-action` + `bind()` 的 if/else 链，或 `data-tab`；**不允许内联 onclick**
4. 移动端优先：基准 390×844，兼容 360×640~430×932；所有可点元素 **≥44×44 CSS px**
5. 每次改完必须自测：`node --check` + 真实点一遍相关流程 + **控制台 0 报错** + 截图与设计稿比对
6. 先出**实施计划**（改哪些文件/函数/新增 CSS 类 + 验证方式），确认后再动手；**每完成一项停下汇报**
7. ⚠️ 先确认要改哪一份：线上部署是 **v2.1.8**、本地源码是 **2.2.0**（`app.js`/`styles.css`/`sw.js` 都不同）。改本地后要同步更新 `version.json`、`index.html` 的版本号、`sw.js` 的 `CACHE` 名，否则发版后玩家会被旧 Service Worker 钉住
