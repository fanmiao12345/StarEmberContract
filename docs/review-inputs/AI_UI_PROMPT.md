## 1. 工程约束（必须先读，违反即失败）

1. 技术栈是**纯静态 HTML/CSS/JS**，无框架、无构建步骤、无 npm 依赖。
   - 主逻辑：`web/app.js`（约 400 行、单文件、`render()` 用 `innerHTML` 整体重建 `#app`，`bind()` 用 `onclick` 绑定所有 `[data-action]`）
   - 数据层：`web/game-data.js`（引擎 + 配置表，导出 `window.STAR_EMBER_GAME`）
   - 样式：`web/styles.css`（约 21 万字符，单一文件）
   - 资源清单：`web/asset-manifest.v20.json` + `web/asset-loader.js`（`window.StarEmberAssets`）
2. **不要引入任何新依赖、不要改成框架、不要拆分文件**（除非我明确要求）。新增样式一律追加到 `styles.css`，命名沿用现有前缀体系（`v216-` / `v218-` / `m2xx-`），并沿用现有的 CSS 变量与配色。
3. **不要动游戏数值与规则**（`game-data.js` 里的概率、消耗、掉落、上限），除非任务明确要求。UI 改版不得改变存档结构 `starEmber.save.v20` 的字段语义。
4. 所有可点元素**必须沿用现有事件模型**：要么用 `<button data-action="xxx">` + 在 `bind()` 的 if/else 链里加分支，要么用 `data-tab="xxx"`。**不允许新增 onclick 内联脚本**。
5. 中文字体、深色科幻美术风格、金色主 CTA（`#f6c453` 系）是既定视觉语言，不要改成其它风格。
6. 目标机型：**移动端优先**，基准视口 390×844，必须兼容 360×640 ~ 430×932，桌面端居中限宽（现有 `--v218-phone` / `max-width:860px` 机制）。所有可点元素 **≥44×44 CSS px**。
7. 每次改完必须自测：
   - 用 `node --check` 确认没有语法错误；
   - 在页面上真实点一遍相关流程，**控制台必须 0 报错**；
   - 截图自查是否与设计稿一致（可用无头浏览器截图）。
8. 改完在文件顶部注释里记录变更（如果有 CHANGELOG 就追加），并在回复里给出「改了哪些文件、哪些函数、怎么验证」。

### 任务 A：把战斗结算面板显示出来（最高优先级，逻辑上只需 1 行）
- 位置：`web/app.js` 的 `async function battle()`。
- **重要澄清**：结算面板 `battleResultOverlay()` **已经写好了，而且完成度很高**（我截过图：顶部 `BATTLE COMPLETE · STAGE N` + `战斗胜利` 大标题 + 关键词 + `阵容战力 / 战斗模式 / 本场 MVP` 三宫格 + `战利品` 区（烬币 +430、契灵印 +1、装备卡「潮纹护甲 · 可优先给 青禾 补齐护甲」）+「查看本场贡献」折叠 + 主按钮）。
  问题只在于：`battle()` 里在 `lastBattle=d.battle` 之后把 `resultOpen=false` 了，而面板只在 `resultOpen===true` 时渲染 —— **所以它永远不显示**。（手动战斗路径 `adoptLiveSession()` 里设的是 `resultOpen=true`，说明是漏改。）
- 要求：
  1. 战斗结束后 `resultOpen=true`；这一步是**一行改动**，请先单独做掉并验证；
  2. 失败时同样显示面板（文案：「挑战失败 · 阵容未被清除」，并给出「再次挑战」/「按建议提升」按钮，复用现有的 `resultRetry`/`resultRecover`）；
  3. 面板显示出来后，**对照设计稿图(8)-05 做增量补强**（不要推倒重写）：设计稿多了 ★★★ **星级评价**、**「战斗统计」快捷入口**、**「获得奖励」区的图标化卡片**、底部 **「返回」/「下一关」双按钮**（现在只有一个「关闭回放结算」全宽按钮）；
  4. 面板必须在弹窗层级上**高于顶栏**（现有 bug：十连结算弹窗 `z-index:82` 低于顶栏 `110`，会被点穿。请统一把结算类弹窗放到 `z-index:5000` 那一档）。

### 任务 B：给战斗加一个"看得见"的场景
- 现状：自动战斗是同步结算，玩家看不到过程。
- 要求（**不要求改战斗算法**）：
  1. 复用现有 `liveBattlePanel()` / `battleArena()` 的思想，做一个**战斗演出层**：上方敌方卡片（名称 + 血条 + Boss 标记），下方我方 5 张角色卡（立绘缩略 + 名称 + 血条 + 技能充能条）；
  2. 用一个**逐帧播放器**把 `lastBattle.timeline`（已存在，含每一帧的动作文本与 `effect`）按 `ui.battleSpeed`（1 / 1.5 / 2）逐帧播放，每帧让受击方血条下降、飘伤害数字、屏幕轻微抖动；
  3. 播放完成后自动进入任务 A 的结算面板；
  4. 提供「跳过演出」按钮（点击立即结算）；
  5. 资源不足以做立绘战斗时，**至少要有**：双方卡片化排版、血条动起来、伤害数字飘字。这是底线。
- 约束：演出层必须能被 `render()` 重建而不丢状态（把播放位置存在全局变量里，参考现有 `battleFrame` 的做法）。

### 任务 C：扫荡结果弹窗（图(8)-06）

- 要求：扫荡结束后弹窗显示「扫荡完成」+ `已完成 N/N 次扫荡` + 所有获得的道具（图标 + 数量）+ 「再次扫荡」/「确定」按钮。
